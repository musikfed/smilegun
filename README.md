# SmileGun v2.1.1

Вторая итерация browser-camera архитектуры. Камеру открывает браузер через `getUserMedia()`, а Python получает только уменьшенные JPEG-кадры и анализирует их MediaPipe. Поэтому Python не требует прямого доступа к webcam через DSHOW/MSMF.

## Что изменено в v2.1.1

- **Отдельное боевое пространство**: мишени, прицел и выстрелы живут внутри отдельной рамки и больше не залезают под HUD и панель камеры.
- **Возвращён квадрат мощности**: заряд увеличивает размер квадратного прицела. Квадрат начинает заметнее дрожать и «набухать» по мере накопления энергии.
- **Размер квадрата = зона выстрела**: большой заряженный квадрат может зацепить сразу несколько мишеней. После обычного выстрела накопленный заряд расходуется.
- **Заряд озвучивается**: каждый новый шаг мощности играет `charge.wav` с увеличивающейся высотой/интенсивностью; сильный выстрел звучит тяжелее.
- **Моргание стало адаптивным**: порог вычисляется относительно твоего собственного уровня открытых глаз и заряд срабатывает на момент закрытия глаз, а не после повторного открытия.
- **Голос «ПЫМ» расширен**: учитываются несколько вариантов, которыми Chrome может распознать короткий звук (`пим`, `пум`, `бум`, `дым`, `пын` и близкие варианты). Для `ПИУ` также используются альтернативы распознавания.
- В правой панели теперь видно текущий показатель глаз и адаптивный порог — это удобно для проверки моргания.
- `run.ps1` теперь ASCII-only, чтобы Windows PowerShell 5.1 не ломал файл из-за UTF-8/BOM.
- **Три независимых способа выстрела**: кулак, голос «ПИУ» и открытие рта больше не используют один общий триггер и не могут блокировать друг друга.
- **Кулак** — обычный одиночный выстрел с коротким зелёно-белым миганием квадрата.
- **«ПИУ»** — отдельный одиночный выстрел: квадрат и зона выстрела кратко становятся красными.
- **Широко открытый рот** — отдельный тройной выстрел: три синих квадрата расходятся по горизонтали. Для защиты от случайного срабатывания при обычной речи используется высокий порог, короткое удержание, гистерезис и cooldown.
- В диагностике справа показывается коэффициент открытия рта и порог срабатывания.

## Архитектура

```text
WebCam
  ↓ browser getUserMedia()
Chrome / Edge
  ↓ JPEG ~416 px, 15 FPS, максимум 1 запрос одновременно
Flask localhost
  ↓ OpenCV imdecode
MediaPipe Face Mesh + Hands
  ↓ JSON state
Browser game
```

## Управление

- **Рука** — двигает квадратный прицел.
- **Моргание** — добавляет заряд.
- **«ПЫМ»** — добавляет заряд.
- **Кулак** — независимый одиночный выстрел, зелёно-белая вспышка квадрата.
- **«ПИУ»** — независимый одиночный выстрел, красная вспышка квадрата.
- **Широко открыть рот** — независимый тройной синий выстрел.
- **100% + улыбка** — супер, уничтожает все цели.
- `Space` — выстрел.
- `C` — ручной шаг заряда.

## Запуск

```powershell
cd D:\smilegun_v2_1
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Или вручную:

```powershell
uv venv --python 3.12
uv sync --python 3.12
uv run python generate_sound.py --ensure
uv run python app.py
```

Открыть:

```text
http://127.0.0.1:5000
```

## Производительность

Проект закреплён на Python 3.12 и рассчитан на ноутбук уровня Ryzen 5 3500U / Vega 8. По умолчанию анализ идёт около 15 FPS. Пока backend занят текущим кадром, новые кадры не ставятся в очередь, поэтому задержка не должна накапливаться.
