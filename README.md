# SmileGun

Небольшая веб-игра на Python: веб-камера отслеживает радужки/зрачки и улыбку, положение взгляда управляет зеленым квадратом, а улыбка вызывает выстрел.

## Требования

Windows + `uv` + Python 3.12. На Windows сначала убедись, что есть `ffmpeg` в PATH:

```powershell
winget install Gyan.FFmpeg
```

## Запуск

```powershell
cd smilegun
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Открой `http://127.0.0.1:5000` и нажми **ЗАПУСТИТЬ КАМЕРУ + ИГРУ**.

## Как это работает

- Камера: OpenCV, поток MJPEG отдаётся на `/video_feed`.
- Лицо, зрачки и рот: MediaPipe Face Mesh с `refine_landmarks=True`.
- **Кубик управляется только зрачками.** Взгляд считается как
  `(зрачок − центр своего глаза) / ширина глаза`. Голова в прицел не входит:
  когда человек двигает головой, глаз и зрачок едут по кадру вместе, поэтому
  отношение не меняется. Поворот и наклон головы прицел не сдвигают.
- **Калибровка.** Кнопка «КАЛИБРОВКА» усредняет 15 кадров и запоминает
  текущее положение зрачков как нейтраль (`gaze_neutral_x/y` в `config.py`),
  дальше прицел считается смещением от неё. В момент нажатия надо смотреть в
  центр поля; «СБРОС» обнуляет нейтраль.
- Взгляд сглаживается экспоненциальным средним (EMA), параметр
  `smoothing_alpha`.
- **Улыбка** — это рот, растянутый в ширину (губы можно сжать, рот открывать
  не нужно): `smile_score = ширина рта / ширина глаза`, в покое ≈1.5, при
  широкой улыбке ≈1.8. Срабатывает по началу улыбки и даёт один выстрел, а
  `smile_hysteresis` не даёт дрожащему у порога значению выдать очередь.
- **Широко открытый рот** (просвет между внутренними губами / ширина глаза,
  параметр `mouth_open_threshold`) даёт **двойной выстрел**.
- Кубик **зелёный всегда** и краснеет только короткой вспышкой (160 мс) в
  момент выстрела: подсветка привязана к выстрелу, а не к тому, как долго
  держится улыбка.
- Прицел приходит на клиент в долях поля (0..1) и рисуется с отступом 22 px
  от рамки, поэтому кубик не уезжает за границу поля.
- Игровое поле рисуется браузером, поэтому не зависит от частоты JPEG-потока.
- Интерфейс адаптивный: ширина меню и размеры шрифтов привязаны к окну (`vw`,
  `em`, `clamp`), поле масштабируется без верхнего ограничения, превью
  подрезается на низких окнах. При масштабе страницы 50% меню не мельчает, а
  поле занимает всю свободную область.
- `static/blaster.mp3` генерируется локально из синтезированного сигнала.

## Настройки (слайдеры в сайдбаре)

| Слайдер | Параметр | Что делает |
|---|---|---|
| Усиление зрачков (X) | `iris_gain` | сколько долей поля даёт единица взгляда |
| Усиление зрачков (Y) | `iris_gain_y` | дополнительный множитель по вертикали |
| Сглаживание | `smoothing_alpha` | EMA, меньше — плавнее |
| Порог улыбки | `smile_threshold` | ширина рта / ширина глаза |
| Гистерезис | `smile_hysteresis` | порог отпускания = threshold × значение |
| Открытый рот → двойной выстрел | `mouth_open_threshold` | просвет губ / ширина глаза |
| Скорость пули | `bullet_speed` | пикс/кадр |
| Громкость звука | — | только в браузере, на сервер не отправляется |
| Ширина/высота поля | `field_width/height` | поле масштабируется под окно |

## HTTP-эндпоинты

- `GET /` — страница игры (`templates/index.html`).
- `GET /state` — `aim_x/aim_y`, `iris_x/iris_y`, `gaze_dx/gaze_dy`,
  `neutral_x/neutral_y`, `smile_score`, `mouth_open_score`, `smile`,
  `mouth_open`, `shot_id`, а также диагностика камеры: `frames_read`, `face`,
  `fps`, `camera_open`, `error`.
- `GET|POST /config` — чтение и изменение параметров из `config.py`.
- `POST /calibrate`, `POST /calibrate/reset` — калибровка взгляда.
- `POST /camera/start`, `POST /camera/stop` — камера.
- `GET /video_feed` — MJPEG-превью.

Проверка окружения: `python diagnostics.py` (без камеры —
`SMILEGUN_SKIP_CAMERA=1`). Подробные логи Flask: `SMILEGUN_VERBOSE=1`.

## Если что-то не работает

Сайдбар показывает диагностику: **FPS камеры**, **Кадров всего**, **Лицо в
кадре**, а красная строка под статистикой — текст ошибки.

- **«НЕТ КАДРОВ»** или красное «Камера открыта, но не отдаёт кадры» —
  устройство занято другим процессом: закрой Teams/Zoom/«Камера» Windows и
  вкладки, использующие веб-камеру, затем нажми «ОСТАНОВИТЬ» и снова
  «ЗАПУСТИТЬ КАМЕРУ». Проверить, кто держит порт: `netstat -ano | findstr :5000`.
- **«НЕТ ЛИЦА»** — кадры идут, но лицо не найдено: сядь в кадр, добавь света.
- **Прицел не двигается, «Зрачок X/Y» = 0.000** — сначала нажми
  «КАЛИБРОВКА», глядя в центр поля; если значения так и нули, значит лицо не
  найдено (см. «Лицо в кадре»).
- Приложение запускается **одним** процессом (`use_reloader=False`): с
  релоадером Flask поднимал второй процесс, `tracker.start()` выполнялся в
  обоих, камеру открывали два процесса — и тот, что получил устройство, не
  обслуживал браузер. Снаружи это выглядело как чёрное превью и «НЕТ КАМЕРЫ».
- Из-за этого же после правок кода сервер нужно перезапускать руками: автоперезагрузки больше нет.
